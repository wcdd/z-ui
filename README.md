# z-ui · realm 端口转发管理面板

一个基于 [realm](https://github.com/zhboner/realm) 的轻量端口转发管理面板，用一条 `z-ui` 命令即可在终端里增删查转发规则，并支持 **3x-ui 节点自动同步**。

适合做中转机（A 机）转发到落地机（B 机）的场景：B 机上的 3x-ui 新增/删除节点后，A 机自动同步出对应端口的转发规则，无需手动维护。

---

## ✨ 功能特性

- **一键安装 realm**：自动识别架构（x86_64 / aarch64），多镜像加速下载，失败可手动上传兜底。
- **转发规则管理**：增、删、查转发规则，每条规则可加中文备注。
- **目标 IP 记忆复用**：新增转发时可从已记忆的 IP 列表里选择，不用每次重复输入同一个落地 IP；也可彻底新增。
- **3x-ui 节点同步监控** ★
  - 通过 3x-ui 3.2.0+ 的 **API Token** 查询目标面板节点（无需账号密码登录）。
  - **严格同端口**：目标新增节点 → 本地自动新增 `本机端口 = 远端端口` 的转发；目标删除节点 → 本地自动删除。
  - 端口被占用或新增失败会写入日志并跳过，不影响其它节点同步。
- **后台守护进程**：独立 systemd 服务 24 小时轮询，崩溃/异常退出后自动恢复，轮询间隔可调（默认 60 秒）。
- **同步日志**：所有新增/删除/失败原因都记录在案，面板内可查看、实时跟踪、清空。
- **轻量依赖**：硬依赖只有 `curl`；JSON 解析优先用 `jq`，没有 `jq` 时自动退回内置 `grep/sed` 解析，多数机器**零额外安装**即可使用。

## 🚀 快速开始

### 方式一：一键安装（推荐）

> 把下面的 `你的用户名/仓库名` 换成你自己的 GitHub 仓库地址。

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/你的用户名/仓库名/main/setup.sh)
```

如果国内网络访问 GitHub 较慢，可用加速镜像：

```bash
bash <(curl -fsSL https://gh-proxy.com/https://raw.githubusercontent.com/你的用户名/仓库名/main/setup.sh)
```

### 方式二：手动下载运行

```bash
# 下载脚本
wget -O setup.sh https://raw.githubusercontent.com/你的用户名/仓库名/main/setup.sh
# 赋予执行权限
chmod +x setup.sh
# 运行（需 root）
sudo ./setup.sh
```

首次运行会自动安装 realm 并把自身注册为 `z-ui` 命令。之后**随时输入 `z-ui` 即可唤出管理面板**：

```bash
z-ui
```

## 📖 使用说明

### 主菜单

```
1. 安装 / 更新 realm
2. 新增转发规则
3. 查看现有转发
4. 删除指定转发
--------------------------------
5. 3x-ui 节点同步监控 ★
6. 管理已记忆的目标IP
--------------------------------
7. 重启 realm 服务
8. 停止 realm 服务
9. 启动 realm 服务
10. 查看 realm 实时日志
--------------------------------
11. 卸载 realm
0. 退出面板
```

### 新增转发规则（手动）

选择菜单 `2`，依次输入：

1. **本机监听端口**：用户/客户端实际访问的端口。
2. **目标 IP**：从已记忆列表选序号，或输入 `0` 彻底新增（新增的会自动记住，下次可直接选）。
3. **目标端口**：落地机上节点的端口。
4. **备注**：可选，如 `TK直播-日本`。

### 配置 3x-ui 自动同步

> 前提：落地机已部署 **3x-ui 3.2.0 或更高版本**，并在面板里生成了 **API Token**。

进入菜单 `5` → `1. 新增监控目标`，依次填写：

| 字段 | 说明 | 示例 |
|------|------|------|
| 监控名称 | 自定义，用于区分多个目标 | `jp-node` |
| 面板地址 | 含端口与 web base path | `https://1.2.3.4:2053/abcdef` |
| API Token | 在 3x-ui 面板生成的 token | `xxxxxxxx` |
| 转发落地 IP | realm 把流量转去的 IP，通常就是该面板服务器 IP | `1.2.3.4` |

保存时会先测试连接。成功后守护进程会自动启动并立即执行一次同步，之后每隔设定的间隔自动同步。

**同步规则说明**：

- 只同步 3x-ui 里**启用中**（enable）的节点。
- 始终保持**本机端口 = 远端端口**。
- 目标新增节点 → 本机自动新增转发；目标删除/禁用节点 → 本机自动删除对应转发。
- 若某端口在本机已被其它规则或进程占用，会**跳过该端口并写错误日志**，不影响其它节点。
- 手动添加的规则（来源标记为 `manual`）不会被同步逻辑删除，二者互不干扰。

### 查看同步日志

菜单 `5` → `5. 查看同步日志`，可查看最近 100 行、实时跟踪（`tail -f`）或清空日志。

### 调整轮询间隔 / 守护进程

菜单 `5` → `6. 同步设置`，可修改轮询间隔（热生效，下一轮起效）、启停/重启守护进程。

## 🔧 工作原理

```
客户端 ──→ A 机 (中转, 装 z-ui + realm) ──→ B 机 (落地, 装 3x-ui)
                    │                              │
                    │   每隔 N 秒通过 Token         │
                    └──── 查询 B 机节点列表 ────────┘
                         自动同步出对应端口转发
```

- realm 主服务：`realm.service`，负责实际的端口转发。
- 同步守护服务：`realm-sync.service`，后台轮询 3x-ui API 并维护转发规则。
- 两个服务都配置了 `Restart=always`，崩溃后自动拉起。

## 📂 文件位置

| 路径 | 说明 |
|------|------|
| `/usr/local/bin/realm` | realm 程序本体 |
| `/usr/local/bin/z-ui` | 管理面板脚本（即本脚本） |
| `/etc/realm/config.toml` | realm 运行配置（自动生成，勿手改） |
| `/etc/realm/rules.db` | 转发规则数据 |
| `/etc/realm/ips.db` | 已记忆的目标 IP |
| `/etc/realm/monitors.db` | 3x-ui 监控目标配置 |
| `/etc/realm/sync.log` | 同步日志 |
| `/etc/realm/sync.conf` | 同步配置（轮询间隔） |
| `/etc/systemd/system/realm.service` | realm 主服务 |
| `/etc/systemd/system/realm-sync.service` | 同步守护服务 |

## ❓ 常见问题

详见 [常见问题文档](docs/常见问题.md)。

几个高频问题：

- **同步报 `HTTP 401`**：Token 无效或鉴权方式不符，检查 3x-ui 版本是否 ≥ 3.2.0、Token 是否正确。
- **面板地址怎么填**：要包含端口和 web base path，例如 `https://1.2.3.4:2053/abcdef`，别漏掉路径那一段。
- **没有 jq 能用吗**：能。脚本会自动尝试装 jq，装不上就用内置 grep/sed 解析，不影响功能。
